# v0.6 — Layer 6: Systems Profiler & Benchmark

> Status: **shipped 2026-06-17**

## Summary

v0.6 extends `agent0waste` with a new layer that benchmarks OpenAI-compatible
inference servers (vLLM, SGLang, or any other compatible endpoint), records
client-side latency / throughput / TTFT / error counts, optionally scrapes
Prometheus `/metrics` for backend counters, and emits a JSON + CSV report
with an explainable 0–100 `waste_score` (lower is better).

v0.6 **does not modify the existing Layers 1–5**; it is strictly additive.
The new subcommand tree is `agent0waste bench { run | compare | report }`.

## Scope (in)

- Three first-class targets: `vllm`, `sglang`, `baseline`.
- Swept-concurrency chat-completion load (default `[1, 4, 16, 32]`).
- Optional Prometheus `/metrics` scraping (1 Hz, stops when the loadgen
  finishes).
- JSON + CSV report outputs.
- Waste score with five axes, proration over unavailable axes.
- A `bench` cargo feature that gates the heavy HTTP runtime so the default
  `cargo install` binary stays lean.
- Backwards-compatible CLI: `agent0waste scan` / `history` / `cost` /
  `pricing` / `intercept` / `run` / `sessions` all unchanged.

## Non-features (out of v0.6)

- **No MLX / oMLX Apple Silicon target.** Deferred to v0.7.
- **No custom kernels.** The `Target` trait is the seam for a future slot,
  but nothing ships in v0.6.
- **No fabricated metrics.** If a backend doesn't expose a series, the
  report shows `null` and the waste score is prorated over the available
  axes. We never invent a "KV cache hit rate" that isn't derivable from
  the exposed metrics.
- **No upstream contributions to vLLM / SGLang.** The standalone benchmark
  is the v0.6 deliverable. Contributing findings upstream is a v0.7+
  conversation once the numbers exist.
- **No continuous / streaming dashboard.** JSON + CSV are the canonical
  outputs. A live TUI is out of scope.
- **No MLX / CUDA / Metal deps.** The `bench` feature pulls in `reqwest`,
  `tokio`, `csv`, `humantime`, `parking_lot`, `rand`, `futures-util`. No
  `mlx-rs`, no `cudarc`, no `objc`, no Metal.

## CLI surface

```
agent0waste bench <target> [flags]    # run benchmark
agent0waste bench compare <a> <b>     # diff two reports, emit waste-score delta
agent0waste bench report <path>       # render a stored report as markdown table
```

`<target>` ∈ { `vllm`, `sglang`, `baseline` }.

### Flags

| Flag | Default | Notes |
|------|---------|-------|
| `--base-url` | (required) | e.g. `http://localhost:8000` |
| `--model` | `default` | Model name passed to the server |
| `--concurrency` | `1,4,16,32` | Comma-separated concurrency levels |
| `--num-requests` | `100` | Requests per concurrency level |
| `--input-tokens` | `512` | Approx input tokens for synthetic prompts |
| `--output-tokens` | `256` | Max output tokens per request |
| `--dataset` | `synthetic` | `synthetic` or `sharegpt` |
| `--dataset-path` | `data/sharegpt-tiny.json` | Override ShareGPT fixture |
| `--stream` | `false` | `stream=true` on the request |
| `--scrape-metrics` | `true` | Poll `/metrics` 1 Hz |
| `--request-timeout` | `30s` | Per-request timeout |
| `--warmup` | `10s` | Warmup duration before sampling |
| `--output` | (none) | JSON report path |
| `--csv` | (none) | Per-sample CSV path |
| `--context-window` | (none) | Model context window (for `context_oversize`) |
| `--duration` | (none) | Run duration cap |

## Waste score

Five axes, each with weight 20. Each axis produces a normalized waste value
in [0, 1]. Final `waste_score` is the weighted sum expressed on a 0–100
scale, prorated over the available axes if any input is missing.

| Axis | Weight | Source | Formula |
|------|--------|--------|---------|
| `kv_cache_pressure` | 20 | scraped KV cache % | mean over run, clamped to [0, 1] |
| `gpu_underutilization` | 20 | scraped GPU util | `1 - mean(gpu_util/100)` |
| `tail_latency` | 20 | client-side p50/p99 | `clamp((p99/p50 - 1) / 4, 0, 1)` |
| `ttft_jitter` | 20 | client-side TTFT samples | `clamp(cv(ttft) / 0.5, 0, 1)` |
| `context_oversize` | 20 | client-side prompt vs ctx | fraction > 0.9 × context window |

`waste_score` is **lower is better**. 0 = no detectable waste on the
measured axes; 100 = every available axis is fully saturated. The existing
"efficiency / if-cleaned delta" framing in the README becomes
`efficiency = 100 - waste_score`.

Missing axes are reported as `null` in the JSON and listed in
`waste_axes_unavailable` so the reader can see exactly what was and
wasn't measured.

## Cargo

```bash
# Default build (no Layer 6):
cargo build --release

# Build with Layer 6:
cargo build --release --features bench
```

The `bench` subcommand errors out at runtime if the feature is not enabled.

## Exit criteria

v0.6 ships when:
- `cargo test --features bench` is green (148 tests).
- `agent0waste bench run vllm` produces a JSON + CSV report end-to-end
  against a running OpenAI-compatible server.
- The waste score is monotonically non-decreasing in any single axis
  (verified by unit tests).
- Missing backend metrics are reported as `null` and prorate the score.

## Manual acceptance check

Documented in `docs/bench-recipes.md` and `docs/roadmap.md`:

- First blog post: two primary numbers — **vLLM remote** and **SGLang
  remote** — each on Llama 3 8B, each clearly labelled with hardware
  config.
- Optional appendix: a `baseline` run against any local OpenAI-compatible
  server.
- **No MLX / oMLX result is required for v0.6.** MLX is a v0.7 deliverable.

## Out of scope (deferred to v0.7+)

- First-class `mlx-lm` / oMLX Apple Silicon target.
- Optional custom-kernel slot via the `Target` trait.
- A `bench dashboard` subcommand that watches an existing server.
- Upstream PRs to vLLM / SGLang with findings.
