# v0.5.0 — fail-closed mode (opt-in policy layer)

## Goal

Add an opt-in `mode = "fail-closed"` that flips the **default
decision** from `Allow` to `Deny` when no heuristic rule fires.
fail-open remains the default for backward compatibility. Users
who want stricter defaults (CI, shared machines, defense in
depth) can opt in.

## Non-goals

- Per-rule `cache_ttl_s` plumbing. Still tracked in v0.4.4 (#10);
  no current use case.
- Linux / cross-platform fail-closed. macOS only (matches
  v0.4.3 scope).
- Network policy on deny. Out of scope; same as v0.4.3.
- Auto-promotion from fail-open to fail-closed. User must
  edit `intercept.toml` and set `mode = "fail-closed"`.

## Mode flag

`~/.config/agent0waste/intercept.toml`:

```toml
# Default: fail-open (v0.4.x behavior). In fail-open mode, the
# decision is Allow when no rule fires.
# mode = "fail-open"

# Opt-in: fail-closed. In fail-closed mode, the decision is
# Deny when no rule fires. Use this when you want the heuristic
# engine to be a default-deny policy layer.
mode = "fail-closed"
```

The flag is read by `intercept check` on every call (not
baked into the shim at install time, unlike `SANDBOX_ENABLED`).
Rationale: a mode change is a config-level decision; the shim
should pick it up on the next call without needing reinstall.

## `Decision::Deny` + exit code 66

```rust
pub enum Decision {
    Allow,                    // exit 0
    Throttle { cooldown_s },  // exit 64
    Prompt { reason },        // exit 65
    Deny { reason },          // exit 66 (NEW in v0.5.0)
}
```

Exit code 66 is unused by the existing v0.4.x shim and is
distinct from 64/65. Choice rationale: 66 is one above
prompt (65), leaving room for future codes (67 = unknown
error, 68 = sandbox-exec missing, etc.).

## §5 vs §7 — the timeout question (first-class decision)

**Decision:** heuristic timeouts and other runtime errors
(§7 failure table) **remain fail-open regardless of mode**.
`mode = "fail-closed"` governs §5 (the decision table); it
does **not** govern §7.

**Rationale:**

- A heuristic timeout is a system failure, not a policy
  outcome. The 500ms shim budget can fire under slow disk,
  cold cache, or high CPU load — exactly the situations
  where reliability matters most.
- Denying legitimate calls on infrastructure failure would
  make fail-closed mode unreliable, undermining user trust
  in the mode.
- Policy layer vs reliability layer separation: fail-closed
  is a *policy* layer (defaults to deny on no-information);
  it is not a *reliability* layer (deny on system failure).

**Implementation:** `pick_decision` returns a `Decision`
based on §5 (rules + their configured actions + mode default
for "no rule fired"). The shim's fail-open path on `intercept
check` timeout / crash is unchanged. The mode flag is only
consulted inside `pick_decision`, not in the shim's wrapper.

**Precedent for future §7 rows:** mode only flips §5, never
§7. Documented here so future maintainers don't try to add
"fail-closed-timeout" without explicit design discussion.

## User-facing recovery: `--agent0waste-bypass` flag

If fail-closed denies a legitimate call, the user needs a
way to unblock without editing config. Options considered:

| Option | Pros | Cons | Verdict |
|--------|------|------|---------|
| Edit `intercept.toml` to `fail-open` | Matches "intentional" semantics | Friction (~30s edit + restart shim) | Backup; default path for unusual cases |
| `--agent0waste-bypass` flag on the shim | Per-call, grep-able in `ps`, no state | Muscle-memory risk | **v0.5.0 ships this** |
| `intercept allow-once <cmd>` subcommand | Explicit, leaves a trail | File-write races, more CLI surface | Rejected; deferred indefinitely |
| Interactive prompt ("deny override? [y/N]") | Reuses prompt infrastructure | Trust the user to type y; muscle memory | Rejected; the prompt path is a heuristic outcome, not a policy override |

**v0.5.0 ships `--agent0waste-bypass`:**

```bash
# Normal hermes call (subject to intercept + fail-closed policy)
hermes chat

# Override: skip intercept check entirely for this call
hermes --agent0waste-bypass chat
```

**Shim behavior:**

```bash
# Strip --agent0waste-bypass if present, log the bypass, exec
# unwrapped. Goes BEFORE the intercept check.
if [ "${1:-}" = "--agent0waste-bypass" ]; then
    echo "[agent0waste: bypass invoked (mode=$MODE); proceeding without policy check]" >&2
    # Audit log: append to ~/.local/share/agent0waste/bypass.log
    if [ -n "${AGENT0WASTE_BYPASS_LOG:-}" ] || [ -d "$HOME/.local/share/agent0waste" ]; then
        echo "$(date -u +%Y-%m-%dT%H:%M:%SZ) $REAL $*" >> "$HOME/.local/share/agent0waste/bypass.log" 2>/dev/null || true
    fi
    shift
    exec "$REAL" "$@"
fi
```

**Properties of the bypass flag:**

- **Long form only** (`--agent0waste-bypass`): avoids collision
  with any short flag the real binary might use. ~26 chars is
  long enough to be intentional, not a habit.
- **No short form**: prevents muscle memory / accidental bypass.
- **Audit log**: every bypass is appended to
  `~/.local/share/agent0waste/bypass.log` (timestamp + command).
  User can `cat` to see their bypass history; user can `rm` to
  clear. We never read this log; it's user-side audit only.
- **Grep-able in `ps`**: `ps aux | grep --agent0waste-bypass`
  shows all in-flight bypassed calls.
- **Bypass + sandbox**: bypass skips intercept check; sandbox
  still applies (if enabled). Bypassing policy doesn't bypass
  isolation.

## Trace step [4] rendering for deny

```
trace: hermes --version
  [1] load          state.db 932 MB mtime 2026-06-04 10:12:02
  [2] cache         MISS (no entry or stale)
  [3] heuristics    cache_bloat → allow
                  prompt_growth → allow
                  auto_routing → allow
                  model_instability → allow
  [4] decision      deny  source=mode-default  (mode=fail-closed)
  [5] cache store   skipped (deny doesn't store)
  [6] sandbox       enabled (profile=...)
  timing            load=24ms  cache=0ms  eval=1ms  store=0ms  total=25ms
```

For deny from a fired rule:

```
  [4] decision      deny  rule=cache_bloat  (cooldown was insufficient)
```

For deny from bypass:

```
  [4] decision      deny  source=bypass  (--agent0waste-bypass)
```

**New `source=mode-default`** attribute makes the cause of
deny unambiguous. v0.4.x's `source=cache` and `source=fail-open`
remain unchanged.

## Shim behavior for deny

```bash
case "$CHECK_RC" in
    0)   maybe_sandbox "$@" ;;                   # allow
    64)  sleep COOLDOWN; do_check; maybe_sandbox "$@" ;;  # throttle
    65)  prompt; maybe_sandbox "$@" ;;          # prompt
    66)  # deny — print reason, do NOT exec
        REASON=$(echo "$CHECK_JSON" | grep -oE '"reason":"[^"\\]*' | head -1 | sed 's/^"reason":"//')
        if [ -n "$REASON" ]; then
            echo "[agent0waste] deny: $REASON" >&2
        fi
        echo "[agent0waste] mode=fail-closed; refusing to exec" >&2
        echo "[agent0waste] override with --agent0waste-bypass, or edit intercept.toml" >&2
        exit 66
        ;;
esac
```

The shim **does not exec the real binary** on deny. This is
the semantic difference between deny and throttle/prompt —
throttle and prompt both eventually exec (after a wait or
user confirmation); deny is a hard no.

## Configuration migration

No migration needed. `mode = "fail-open"` is the default and
is implicit (no key in the file). Users who set
`mode = "fail-closed"` opt in.

The shim's `mode` line in the install message:

```
note: ~/.config/agent0waste/intercept.toml sets mode=fail-closed
      every call is policy-gated; use --agent0waste-bypass to override
```

(Only printed when the flag is set; fail-open is silent.)

## Tests (planned)

- `pick_decision` returns `Decision::Deny` when no rule fires
  and mode=fail-closed
- `pick_decision` returns `Decision::Allow` when no rule fires
  and mode=fail-open (default behavior preserved)
- `pick_decision` returns the user's configured action when
  a rule fires, regardless of mode (user's config wins)
- Shim bypass flag: present → skip intercept check, log to
  stderr, exec unwrapped
- Shim bypass flag: absent → normal flow
- Shim deny rc 66 → no exec, exit 66, stderr message
- Trace step [4]: renders `deny` with `source=mode-default` /
  `source=bypass` / `rule=<fired>` correctly

## Validation (planned)

1. Set `mode = "fail-closed"` in `intercept.toml`
2. Reinstall hermes shim
3. Run `hermes --version` → expect: deny (no rule fires on
   `--version` alone)
4. Verify shim prints `[agent0waste] deny: ...` and exits 66
5. Verify real hermes does NOT run (no `Hermes Agent v0.15.1` output)
6. Run `hermes --agent0waste-bypass --version` → expect:
   bypass log line, real hermes runs
7. Verify `bypass.log` contains the bypass entry
8. Run `intercept trace --command "hermes --version"` in
   fail-closed mode → expect `[4] decision deny source=mode-default`
9. Trigger a heuristic (call hermes a few times to populate
   cache_bloat) → run trace → expect `[4] decision deny
   rule=cache_bloat`
10. Switch back to `mode = "fail-open"` (or remove the line) →
    regression: all v0.4.1 paths still pass

## Open questions

1. **Bypass + sandbox**: when bypass is invoked, do we still
   wrap the real binary in sandbox-exec? **Proposed yes** —
   bypass is a *policy* override, not an *isolation* override.
   If the user wants to disable sandbox for one call, they
   can `intercept disable-sandbox` first. Documented above.

2. **Bypass + audit log on non-macOS**: the audit log uses
   POSIX `date -u` and `>>` redirect. Works on Linux too,
   but v0.5.0 ships macOS-only. Verify the audit log works
   on Linux before opening up the platform.

3. **Should the bypass log be opt-out?** Some users might
   find it noisy. **Proposed default-on**: the audit log
   is the whole point of having a visible bypass trail.
   If a user wants to disable, they can `chmod 000
   bypass.log` and the shim will silently fail to write.

4. **What's the deny exit code in CI scripts?** 66 is a
   bash signal for "out of memory" (rarely seen). Distinct
   from 64/65 but not standard. We could use 77 instead
   ("EX_NOPERM" in sysexits.h). 77 might be more
   recognizable. **Proposed 66 for now** (closer to 64/65,
   semantically "deny" follows "throttle" / "prompt");
   revisit if CI tools complain.

## Out of scope reminder

This is **fail-closed mode only**. Per-rule `cache_ttl_s`
plumbing is still v0.4.4 (#10) and is NOT a prerequisite
for v0.5.0. v0.5.0 changes one default (Allow → Deny on
no-rule-fired); it doesn't change per-rule semantics.

Local LLM proxy (#6) is v0.6.0. v0.5.0 only affects the
decision layer for shim-wrapped commands.
