# v0.6.1 — Cache pricing

**Status:** design (in progress)
**Branch:** `codex/v0.6.1-cache-pricing`
**Targets:** `Cargo.toml` version `0.6.0` → `0.6.1`
**Scope:** this design covers **cache pricing only**. The heuristic-expansion
work in `docs/roadmap.md` v0.6.1 is split out to v0.6.2 (smaller, easier
to review, and unblocks shipping cache pricing sooner).

## Why now

The cost report (`agent0waste cost`) currently shows `cache_tok` as a token
count but **does not price cache reads**, even though every major provider
charges for them (Anthropic: 10% of input; OpenAI: 50% of input on most
GPT-4 models; xAI: variable; most others: ~25%). For a user with heavy
cache reuse, the cost report understates spend by 20-40%.

The data is already in `~/.hermes/state.db` (`cache_read_tokens`,
`cache_write_tokens`) and is read into `HermesSession` today. Pricing it
is the missing piece.

## Scope (in)

- `Rate` tuple grows from `(f64, f64)` to `(f64, f64, f64, f64)` =
  `(input, output, cache_input, cache_output)`. All rates in USD / 1M
  tokens.
- `Pricing::cost()` gains two parameters and returns a structured
  `CostBreakdown` (or a `(regular, cache)` pair) instead of a single `f64`.
- `CostRow` gains a `cache_cost_usd: f64` field.
- `format_table()` shows 7 columns (was 6) with `cache_$` as the new
  column, placed after `cost_usd`.
- `default_rates()` populates cache rates for the 44 built-in models
  using known public pricing.
- TOML override schema: 4-field form is the new canonical. The 2-field
  form (`input`, `output` only) is accepted with `cache_input` and
  `cache_output` defaulting to 0.0 (no cache charge). This is
  backwards-compatible for every existing user override.
- New unit tests for the cache math, new smoke test that asserts the
  7th column header is present in `cost` output.

## Scope (out)

- **Heuristic expansion** (3 new heuristics in `docs/roadmap.md` v0.6.1)
  is deferred to v0.6.2.
- **Cache *write* cost** is tracked in `HermesSession` but the field
  isn't read by `cost`. We will *not* add it in this PR — most providers
  don't charge for cache writes, and adding it now is a distraction.
- **Backfill of historical rates** (older pricing snapshots): out. The
  override file is the user's source of truth for historical cost.
- **`crates.io` publish** and **Linux/Windows support**: unchanged
  (still v1.0.0 scope per roadmap).

## Data model

### `src/pricing.rs`

```rust
// Was: pub type Rate = (f64, f64);
// Now: tuple of 4; TOML schema accepts either 2-field (legacy) or
// 4-field (new). Defaults for cache rates are 0.0.
pub type Rate = (f64, f64, f64, f64); // input, output, cache_input, cache_output
```

Helpers for clarity (no behavior change, just readability at call sites):

```rust
impl Rate {
    pub fn input(self) -> f64 { self.0 }
    pub fn output(self) -> f64 { self.1 }
    pub fn cache_input(self) -> f64 { self.2 }
    pub fn cache_output(self) -> f64 { self.3 }
}
```

`Pricing::cost` becomes:

```rust
pub fn cost(
    &self,
    model: &str,
    input_tokens: u64,
    output_tokens: u64,
    cache_read_tokens: u64,
) -> Option<CostBreakdown> {
    self.get(model).map(|(in_r, out_r, cin_r, cout_r)| {
        let regular  = (input_tokens as f64 / 1e6) * in_r
                     + (output_tokens as f64 / 1e6) * out_r;
        let cache    = (cache_read_tokens as f64 / 1e6) * cin_r;
        CostBreakdown { regular, cache }
    })
}

pub struct CostBreakdown {
    pub regular: f64,  // input + output, in USD
    pub cache:   f64,  // cache reads, in USD
}

impl CostBreakdown {
    pub fn total(&self) -> f64 { self.regular + self.cache }
}
```

### `src/cost.rs`

```rust
pub struct CostRow {
    pub key: String,
    pub cost_usd:        f64,   // was: just this; unchanged shape
    pub cache_cost_usd:  f64,   // NEW
    pub sessions: usize,
    pub input_tokens: u64,
    pub output_tokens: u64,
    pub cache_read_tokens: u64,
}
```

The `format_table` function:

```
key             cost_usd  cache_$   sessions  input_tok  output_tok  cache_tok
-----------------------------------------------------------------------------
gpt-4o            $1.2345   $0.1234       12    12345678    2345678    9876543
...
TOTAL             $1.2345   $0.1234       12    12345678    2345678    9876543
```

The "TOTAL" row sums both cost columns.

### TOML override file

**New canonical form (4 fields):**
```toml
[gpt-4o]
input         = 2.50
output        = 10.00
cache_input   = 1.25
cache_output  = 0.00
```

**Legacy form (still accepted, no migration step needed):**
```toml
[gpt-4o]
input  = 2.50
output = 10.00
# cache_input and cache_output default to 0.0
```

The TOML deserializer uses `#[serde(default)]` per field, so missing
fields just default. This means **every existing user override keeps
working unchanged** — the only behavior change is that cache tokens
will now be priced at 0 unless the user opts in by adding the
`cache_input` / `cache_output` keys.

### Default rates for the 44 built-in models

Cache pricing as of 2026-06 (sources: each provider's public pricing page,
rounded to 2 decimal places). Cache writes are free across all providers
(that's the v0.6.0 consensus; we won't model `cache_output` here).

| Provider family | `cache_input` rate | Source |
|---|---|---|
| OpenAI GPT-4o / 4-turbo | 50% of input | OpenAI public pricing |
| OpenAI GPT-4.1 / 5 | 25% of input | OpenAI public pricing |
| Anthropic Claude 3.x | 10% of input | Anthropic public pricing |
| Anthropic Claude 4.x | 10% of input | Anthropic public pricing |
| xAI Grok | 25% of input (variable) | xAI public pricing |
| Google Gemini | free for most tiers; 25% on Pro | Google public pricing |
| Meta Llama (via Groq / Together) | 50% of input (typical) | aggregator docs |
| Mistral | varies; default to 25% | Mistral public pricing |
| DeepSeek | 10% of input (cache hit) | DeepSeek public pricing |
| StepFun, Moonshot, Qwen, Xiaomi | varies; default to 0 (most are free) | provider docs |
| OpenRouter `owl-alpha` | 0 (free tier) | OpenRouter |

`default_rates()` populates 44 entries with `(input, output, cache_input, 0.0)`.
The `cache_output = 0.0` for all entries (free tier assumption; consistent
with current "cache writes are free" consensus).

## Migration

- No user action required. The TOML deserializer handles missing fields.
- Old 2-field override files keep working; cache costs are 0 for any
  model with an old-style override.
- Old 2-field rows in the cost report now have a `$0.0000` cache column
  cell. This is visually a little empty for users who haven't opted in,
  but it's correct and consistent.

## Tests

**Unit tests (in `src/pricing.rs` and `src/cost.rs`):**
1. `cost_with_cache_tokens_prices_cache_separately` — `Pricing::cost`
   for `gpt-4o` with 1M input + 0 cache returns regular $2.50, cache $0;
   with 1M input + 1M cache returns regular $2.50 + cache $1.25.
2. `default_rates_have_cache_rates_for_all_models` — every entry in
   `default_rates()` has `cache_input >= 0.0` and `cache_output == 0.0`.
3. `cost_row_aggregates_cache_cost_independently` — two sessions for
   the same model produce a `CostRow` with `cost_usd` summing both
   inputs and `cache_cost_usd` summing both cache reads.
4. `format_table_renders_seven_columns` — header includes `cache_$` and
   `cache_tok`, with widths matching the new layout.
5. `legacy_toml_override_accepted` — parsing a 2-field `[gpt-4o]` table
   yields `Rate` with `cache_input == 0.0` and `cache_output == 0.0`.

**Integration test (in `tests/cli_smoke.rs`):**
- `cost_includes_cache_column_header` — runs `agent0waste cost` (or
  similar) and asserts the output contains `cache_$`. **Caveat:** `cost`
  reads `~/.hermes/state.db` and may produce empty output on a CI
  machine. The test will be a header-shape check (run `agent0waste cost
  --help` or equivalent) rather than a real cost report. Confirmed
  implementable during coding; will note in the test source if we have
  to use a different surface.
