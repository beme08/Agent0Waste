# Agent0Waste v0.4.0 — Interception (design)

> Block the call before it costs the token.

This is the Layer 4 design. It builds on:
- v0.1.0-alpha (Scanning) — installed
- v0.2.0-beta (Accounting scaffold) — installed
- v0.2.1 (Real token data from `state.db`) — installed
- v0.3.0 (Heuristics) — installed
- v0.3.1 (Pricing UX + heuristic refinement) — installed

**Status:** shipped as v0.4.0-beta on 2026-06-03. Shim install model
is the one described in Mechanism A (UV-style shim dir at
`~/.local/share/agent0waste/shims/`). Exit criteria below are met.

---

## The problem

Layers 1-3 are observers. They tell you what *happened*. Layer 4
tells you what to do *before* the next call. The user's question
goes from "how much did I spend yesterday?" to "how do I stop
spending like that?"

Three failure modes drive the design:

1. **Cache abuse.** A user with a 194M-token cache read tail is
   paying for the same context window 50 times. The call is fast,
   so Hermes doesn't notice. A heuristic that *fires after the
   fact* doesn't help; the user needs to be told *before* the
   50th call that the 49 prior calls were all re-reading the
   same context.

2. **Auto-routing accumulation.** A user with `model = "auto"`
   gets 142 sessions in a week, 3.5M input tokens, $0 visible
   cost (because the auto-routed model is free tier today). Next
   week the auto-router picks a paid model, and the user
   discovers $30 of spend they didn't authorize. The heuristic
   needs to fire *before* the first paid call.

3. **Prompt growth.** A user's prompt grew 3.9x week-over-week.
   Every call is now 4x the input cost. By the time the heuristic
   flags it, the user has spent 4x for a week. The
   throttle/prompt step needs to interrupt *now*.

---

## The hook — where Layer 4 lives

There are four places we could intercept. We rank them by
intrusiveness, transparency, and Hermes compat:

| Mechanism | Intrusiveness | Transparency | Hermes compat | Verdict |
|---|---|---|---|---|
| **A. Shim binary** | Low | High (auditable file) | Trivial | **Default for v0.4.0** |
| **B. Local LLM proxy** | Medium | Medium | Trivial | Deferred to v0.4.1 |
| **C. Config provider** | High | High | Requires Hermes support | Not now |
| **D. Library interpose** | High | Low | macOS-only, fragile | Not now |

### Mechanism A: shim binary (default for v0.4.0)

Today, the user runs Hermes directly:

```
$ hermes run "fix the bug in auth.rs"
```

After `agent0waste intercept enable hermes`, the user has a
shim at `~/.local/bin/hermes` that is earlier on `$PATH` than
the real Hermes binary:

```
$ which hermes
/Users/user/.local/bin/hermes   # the shim
$ cat /Users/user/.local/bin/hermes
#!/usr/bin/env bash
# installed by agent0waste intercept enable v0.4.0
# disable with:  agent0waste intercept disable hermes
...
```

The shim:

1. Reads the command name from its own `$0` (so it knows
   it's wrapping `hermes`, not `claude`)
2. Captures the command line (`model`, `tokens` hints)
3. Calls `agent0waste intercept check --model <hint> --tokens <hint> --command "$*" --source cli`
   with a hard timeout (5s in v0.4.0; 500ms target in v0.4.1+)
4. Agent0Waste reads `state.db`, runs heuristics, returns a JSON decision
5. The shim acts on the exit code:
   - **0 (allow)** → runs the real Hermes (found via `command -v` minus self)
   - **64 (throttle)** → sleeps the cooldown, re-checks once, then runs
   - **65 (prompt)** → prints message to stderr, asks `[y/N]`, runs or aborts
   - **anything else / timeout** → fail-open: log to stderr, run unwrapped
6. Records the result as a SessionRecord via the existing
   `run --` machinery (Layer 2 reuse)

**Why this wins for v0.4.0:**
- **Transparent.** `cat ~/.local/bin/hermes` shows the wrapper.
  No hidden RC edits, no opaque function in `.zshrc`. Developers
  can audit it in 30 seconds.
- **Per-command opt-in.** `intercept enable hermes` only wraps
  `hermes`. `intercept enable claude` only wraps `claude`. The
  user can incrementally opt in.
- **Easy to disable.** `intercept disable hermes` deletes the
  shim. No "did I edit the right RC file?" anxiety.
- **Survives profile reloads.** The shim is a real file on disk;
  sourcing `~/.zshrc` doesn't re-run anything.
- **Zero Hermes changes** — we wrap the user, not the agent.
- **Cross-platform.** `~/.local/bin/` is a XDG-style convention
  on Linux; on macOS we use the same path (it's in default
  `PATH` for Homebrew installs). On Windows we'd need a
  v0.6.0-compatible shim approach; deferred.

**Why the shim approach beat the RC-file approach (rejected):**

The original v0.4 design proposed editing `~/.zshrc` and
`~/.bashrc` to install the wrapper as a shell function. That
approach was rejected for v0.4 final because:

- Modifying RC files is invisible — the user has to `grep` their
  own dotfiles to see what changed.
- Shell functions survive shell restarts and the user forgets
  they exist.
- Sourcing a corrupted RC file (e.g., a wrapper that errors)
  breaks the user's shell. A bad shim just errors on its
  specific command.
- Auditing is harder: `cat ~/.zshrc | grep hermes` is one of
  many lines; `cat ~/.local/bin/hermes` is the whole file.
- Uninstall is harder: the user has to manually find and remove
  the function. A bad shim is a one-line `rm`.

The shim binary is a strictly more transparent, more reversible
approach. The tradeoff is that `~/.local/bin` must be on `$PATH`
and must sort *before* the directory containing the real
command. Both are true for standard Homebrew/uv/pyenv-style
installs; both are documented in `intercept enable`'s output.

### Mechanism B: local LLM proxy (v0.4.1+)

The user points Hermes's `LLM_BASE_URL` at
`http://127.0.0.1:7821/v1`, which is Agent0Waste's local proxy.
Agent0Waste receives every LLM call, decides, and either
forwards to the real provider or short-circuits.

**Why this loses for v0.4.0:**
- Requires Hermes to support a custom base URL (it does, but
  every Hermes profile needs reconfiguration)
- Requires Agent0Waste to translate OpenAI / Anthropic / xAI
  request shapes — significant scope creep
- The proxy must be running (a daemon) — violates the
  project-wide non-goal "no daemon"
- Single point of failure: a buggy proxy breaks all LLM calls

This becomes a follow-up if the shim proves insufficient.
v0.4.1 / v0.5.0 candidate.

## The decision — what Layer 4 does

`agent0waste intercept check` returns one of three decisions:

| Decision | Exit code | What the wrapper does |
|---|---|---|
| `allow` | 0 | Run the command. |
| `throttle` | 64 | Sleep N seconds, re-check once, then run. |
| `prompt` | 65 | Print a message to stderr; ask the user `[y/N]`; abort if no. |

The output is a small JSON document on stdout (parseable) and
a human message on stderr (readable):

```json
{
  "decision": "throttle",
  "reason": "cache_bloat: openrouter/owl-alpha has 12x cache_read/input ratio (5 sessions, 1.2M cache tokens)",
  "hint": "trim the context window or pin a smaller model",
  "cooldown_s": 30
}
```

### Mapping heuristics to decisions

This is the rule table for v0.4.0. Each heuristic has a default
severity and a default action. The user can override per-rule
in `~/.config/agent0waste/intercept.toml`.

| Heuristic | Default severity | Default action | Configurable? |
|---|---|---|---|
| H1 cache_bloat (high) | High | **throttle** (30s) | severity + cooldown |
| H1 cache_bloat (low) | Medium | **prompt** | severity + message |
| H2 prompt_growth (high) | High | **prompt** | severity |
| H2 prompt_growth (low) | Medium | **throttle** (60s) | severity + cooldown |
| H3 auto_routing | Info | **allow** (just log) | yes — but see below |
| H4 model_instability | Info | **allow** (just log) | yes — but see below |
| (no heuristics fire) | — | **allow** | n/a |

### Why are H3 and H4 "allow" by default?

A reasonable first read of this table is: "H3 and H4 are
heuristics that exist in `cost --warnings` but do nothing in
the intercept. Is the implementation untrustworthy?"

The answer is **neither**: H3 and H4 are *informational* by
design, and their `allow` default is intentional, not a
fallback for missing trust. The reasons:

1. **Auto-routing is the user opting in to exploration.** When
   `model = "auto"`, the user has explicitly told Hermes
   "you pick." Blocking or throttling that call would
   contradict the user's choice. The heuristic exists to
   surface the *cost* of that choice in `cost --warnings`,
   not to override it.
2. **Model instability is the user A/B testing.** A user with
   3+ different models in a week is most likely
   experimenting, comparing quality, or iterating. That's
   not waste — it's the user being deliberate. Throttling
   the experiment would be paternalistic.
3. **Both fire at Info severity, not High or Warn.** The
   v0.3.0 heuristic implementation chose Info for these
   findings precisely because the action is "inform, don't
   intervene." If we later find a stronger signal (e.g.,
   "model instability *plus* cost growth"), H3/H4 could
   escalate to Warn or High in a future version.
4. **The cost report is the surface; the intercept is the
   lever.** `cost --warnings` is where H3/H4 should change
   user behavior. The intercept is for high-confidence
   "this call is wasteful" signals, which is H1/H2.

**A user who disagrees can override:** setting
`[rules.auto_routing] action = "throttle"` in
`intercept.toml` makes the wrapper act on H3. The default is
not a hard-coded "do nothing" — it's "do not act
paternalistically by default." A user who wants paternalism
can opt in.

A single call can trigger multiple heuristics. The **highest
severity wins**:

1. High → throttle or prompt (whichever the rule says)
2. Medium → throttle or prompt
3. Low/info → allow

If multiple rules of the same severity fire, we pick the most
specific (cache_bloat beats auto_routing at the same severity).

### Fail-open vs fail-closed (the design choice)

If Agent0Waste is unreachable, the LLM call must proceed. This
is the **fail-open** default. Rationale: the wrapper is a
guardrail, not a gate. Losing the guardrail should not break
the user's workflow.

| Mode | What happens when Agent0Waste is unreachable |
|---|---|
| **fail-open** (default) | LLM call proceeds. Warning is logged to stderr. |
| **fail-closed** (opt-in, `intercept strict`) | LLM call is blocked. User is told to retry or disable strict mode. |

The mode is set at `intercept enable` time and stored in
`~/.config/agent0waste/intercept.toml`. It is not changeable
per-call.

v0.4.0 ships **fail-open only**. Fail-closed is a v0.4.1 or
v0.5.0 addition (it's a one-line change to the wrapper's
error-handling branch, but the UX (error message, retry
behavior) needs design).

### What "Agent0Waste is unreachable" means

Four failure modes trigger the fail-open path. **All four
emit a stderr message** so the user knows the guardrail is
off — the bypass is never silent.

1. **agent0waste binary not on PATH.** The shim falls back to
   running the original command directly. Warning:
   `agent0waste: not on PATH; running unwrapped.`
2. **agent0waste check exits non-zero with no JSON.** Treat
   as unreachable, run unwrapped, log:
   `agent0waste: check failed (exit N); running unwrapped.`
3. **agent0waste check hangs longer than the timeout.** The
   shim kills it, runs unwrapped, logs:
   `agent0waste: check timed out (5s); running unwrapped.`
4. **state.db is missing or locked** (Hermes is actively
   writing, or the user hasn't installed Hermes at all). The
   `intercept check` subcommand itself returns `allow` and
   exits 0 — the shim never sees this case. The check
   subcommand logs:
   `agent0waste: state.db not readable; fail-open allow.`

### Timeouts: v0.4.0 vs target

| Version | Check timeout | Why |
|---|---|---|
| v0.4.0 | **5s** | Real-world SQLite reads on a 900MB state.db take 200-800ms cold, 1-2s warm. 5s is comfortable for the worst case. |
| v0.4.1+ (target) | **500ms** | Once we cache the heuristic output (TTL 30s, invalidated on `run --` recording), the check becomes a HashMap lookup. 500ms is the user-perceptible threshold for "did the intercept add latency?". |

The timeout is hardcoded in the shim script for v0.4.0. It
becomes a config value (`intercept.toml` → `[shim] timeout_ms`)
in v0.4.1.

**Bypass is logged, not silent.** Every fail-open path emits a
distinct stderr message. The shim is the source of the
timeout-killed message; the `intercept check` subcommand is
the source of the missing/locked-db message. Together they
cover the four failure modes.

If the user wants zero stderr noise, they can `2>/dev/null`
their invocations — but by default the guardrail tells the
user when it can't guard.

## The user experience

### Install and enable

```
$ cargo install agent0waste
$ agent0waste intercept enable hermes
✓ installed shim at /Users/user/.local/bin/hermes
✓ shim is ahead of /opt/homebrew/bin/hermes on PATH
  (audit:  cat /Users/user/.local/bin/hermes)
  (disable: agent0waste intercept disable hermes)
$ hermes run "fix the bug"
[agent0waste] allow: no findings in last 24h
... (Hermes runs normally)
```

### Throttle (cache_bloat high)

```
$ hermes run "refactor auth"
[agent0waste] throttle: cache_bloat: grok-4.3 has 9x cache_read/input
ratio in last 7d (12 sessions, 3.2M cache tokens). Sleeping 30s.
... (sleeps 30s)
[agent0waste] re-checking... still high. Running anyway.
... (Hermes runs)
```

### Prompt (prompt_growth high)

```
$ hermes run "add tests for the new feature"
[agent0waste] prompt: prompt_growth: cli prompts grew 2.8x in last 7d
  recent 3d avg: 4,200 in / session
  prior 3d avg: 1,500 in / session
  hint: are you accumulating context? consider a fresh session
continue? [y/N] N
$ (user cancels)
```

### Info (auto_routing, no action)

```
$ hermes run "summarize the PR"
[agent0waste] info: 142 auto-routed sessions in last 7d
  hint: pin a model for predictable cost
... (Hermes runs, command proceeds)
```

### Fail-open: state.db missing

```
$ hermes run "summarize the PR"
[agent0waste: state.db not readable; fail-open allow]
... (Hermes runs, command proceeds)
```

### Fail-open: check timed out

```
$ hermes run "summarize the PR"
[agent0waste: check timed out (5s); running unwrapped]
... (Hermes runs, command proceeds)
```

### Disable

```
$ agent0waste intercept disable hermes
✓ removed /Users/user/.local/bin/hermes
$ which hermes
/opt/homebrew/bin/hermes   # back to the real one
```

## The interface

### `agent0waste intercept` subcommand

```
agent0waste intercept
  enable <command>    install shim for <command> in ~/.local/bin/
  disable <command>   remove shim for <command>
  status              show installed shims + current mode + rule table
  check               run heuristics on current state, return decision
  run -- <cmd>        wrap a single command (used by the shim)
  rules               print the rule table
```

`enable` and `disable` take a command name. Examples:

```
agent0waste intercept enable hermes
agent0waste intercept enable claude
agent0waste intercept enable hermes --force   # overwrite existing shim
agent0waste intercept disable hermes
```

`check` is the unit-testable surface. It takes the same
flags as the shim:

```
agent0waste intercept check \
  --model <hint> \
  --tokens <hint> \
  --command <cmd> \
  --source <cli|cron>  # default cli
```

It prints a JSON decision to stdout and exits 0/64/65.

`run --` is the inner-wrapper that the shim uses. The shim
calls it (not `check` directly) so the SessionRecord is
written by the same code path the user has been using since
v0.2.0-beta.

### `~/.config/agent0waste/intercept.toml`

```toml
mode = "fail-open"  # or "fail-closed" (v0.4.1+)

[rules.cache_bloat]
severity = "high"        # high | medium | low | info
action   = "throttle"    # throttle | prompt | allow
cooldown_s = 30

[rules.prompt_growth]
severity = "high"
action   = "prompt"

[rules.auto_routing]
severity = "info"
action   = "allow"

[rules.model_instability]
severity = "info"
action   = "allow"
```

If the file is missing, defaults are used. The user can
override per-rule but not the mode (mode is set at
`enable` time, not via the file).

## The data flow

```
                   ┌──────────────────────┐
                   │ ~/.hermes/state.db   │
                   │  (5726 sessions)     │
                   └──────────┬───────────┘
                              │ read_recent(since, path)
                              ▼
┌────────────────┐    ┌──────────────────────┐
│ Hermes call    │───▶│ agent0waste          │
│ (or any cmd)   │    │ intercept check      │
└────────────────┘    │                      │
       │              │ 1. load pricing.toml │
       │              │ 2. run heuristics    │
       │              │ 3. apply rules       │
       │              │ 4. emit decision     │
       │              └──────────┬───────────┘
       │                         │ JSON {decision, reason, hint}
       │                         ▼
       │              ┌──────────────────────┐
       │              │ wrap.sh              │
       │              │  exit 0  → run cmd   │
       │              │  exit 64 → throttle  │
       │              │  exit 65 → prompt    │
       │              └──────────┬───────────┘
       │                         │
       ▼                         ▼
   LLM call               stderr log
   proceeds               (record_history)
```

The `check` subcommand is a pure function of:
- `state.db` (read)
- `intercept.toml` (read)
- `pricing.toml` (read, from v0.2.0-beta)
- The flags (model, tokens, command, source)

No state is written by `check`. State is written by `wrap.sh`
(via the existing `run --` recording from v0.2.0-beta).

## Exit criteria for v0.4.0

A release of v0.4.0 is justified when **all** of these are met:

1. **`agent0waste intercept check` works.**
   - Reads `state.db`, runs heuristics, returns a decision
   - Unit tested with synthetic `state.db` and a temp
     `intercept.toml`
   - Tested against the real `state.db` and produces the same
     findings as `cost --warnings` (the heuristic engine is
     unchanged from v0.3.0)
   - **State.db failure modes tested:** missing file, locked
     file, corrupt file. All three return `allow` + log
     + exit 0. No panics.

2. **`agent0waste intercept run -- <cmd>` works.**
   - Exits 0/64/65 based on the decision
   - Throttle: sleeps the cooldown, re-checks once
   - Prompt: prints to stderr, reads from stdin
   - Records the result via the existing `run --` machinery

3. **`agent0waste intercept enable <command>` works.**
   - Installs a shim at `~/.local/bin/<command>`
   - **Refuses to overwrite** an existing shim unless `--force`
     is passed
   - The shim is a real file the user can `cat` to audit
   - No edits to `~/.zshrc`, `~/.bashrc`, or any RC file
   - Creates `intercept.toml` with defaults if missing
   - `intercept status` shows: enabled shims, mode=fail-open, 4 rules

4. **End-to-end demo.**
   - User runs a "warm" prompt 5x in a row
   - On the 5th, `intercept check` returns `throttle`
   - The shim sleeps, re-checks, runs
   - User sees the throttle message and the unblocked command
   - Demo MP4 captured (or GIF, matching v0.1 style)

5. **Fail-open is real and logged.**
   - **No agent0waste on PATH:** shim runs the real command
     and logs `agent0waste: not on PATH; running unwrapped.`
   - **Check exits non-zero with no JSON:** shim runs the real
     command and logs `agent0waste: check failed (exit N);
     running unwrapped.`
   - **Check hangs longer than 5s:** shim kills the check,
     runs the real command, logs `agent0waste: check timed
     out (5s); running unwrapped.`
   - **State.db missing or locked:** `intercept check` returns
     `allow` + logs `agent0waste: state.db not readable;
     fail-open allow.`
   - **None of the four paths is silent.** All emit a distinct
     stderr message.

6. **No code edits to `~/.hermes/config.yaml`, `~/.zshrc`,
   `~/.bashrc`, or any other config file.** Two non-goals are
   preserved: no config edits, no RC edits.

## Non-goals for v0.4.0

- **Fail-closed mode.** v0.4.0 is fail-open only. Fail-closed
  is a v0.4.1 line change but the UX needs more design.
- **Per-call decision override.** The user can't say "let this
  one through even though heuristics would throttle". They have
  to disable the rule, which is too coarse. Deferred to v0.4.1.
- **Daemon mode.** No background process. The wrapper is
  per-invocation. (We're explicitly preserving the "no daemon"
  non-goal.)
- **Cross-agent interception.** v0.4.0 wraps any command, not
  just Hermes. We don't claim to understand what Hermes is
  doing under the hood; we observe the call. Claude Code
  adapter is a v0.5.0 concern (see ROADMAP).
- **Persistent decision log.** The SessionRecord from the
  existing `run --` machinery is the decision log. We don't
  add a separate one.

## Open questions

These don't block v0.4.0 but should be answered before v0.4.1:

1. **What if `~/.local/bin` is not on `$PATH`?** v0.4.0
   detects this at `intercept enable` time and prints a
   one-line instruction:
   `add this to ~/.zshrc:  export PATH="$HOME/.local/bin:$PATH"`
   We do **not** edit the RC file (the shim approach
   deliberately avoids RC edits; the user can decide whether
   to add to PATH). Fish, nushell, xonsh all support
   `~/.local/bin` on PATH; this is universal.
2. **What if `~/.local/bin/hermes` shadows something the
   user already has there?** `intercept enable hermes`
   refuses to overwrite an existing file unless `--force` is
   passed. The existing file is preserved and the user is told
   to `intercept enable hermes --force` if they want to
   overwrite.
3. **What about sudo'd Hermes calls?** The shim doesn't help
   with `sudo hermes` because `~/.local/bin` is not on root's
   PATH. Documented as a known limitation; fix in v0.4.1 if
   anyone hits it (a `/usr/local/bin/agent0waste-sudo` shim
   is a possible v0.4.1 design).
4. **Should the heuristics input be the *next* session or the
   *last 7 days*?** Current plan: last 7 days (consistent with
   `cost --since 7d`). The user's "next call" is judged against
   the recent pattern, not the single next call. This is the
   same input as `cost --warnings` so the two stay aligned.
5. **What if the user has the real `hermes` also in
   `~/.local/bin`?** (Common with Homebrew + uv shims.) The
   shim finds the real binary by stripping `~/.local/bin`
   from `PATH` and re-resolving `hermes`. This is a documented
   edge case in the shim; the test plan covers it.

## Test plan

Tests are split into four layers:

1. **Unit tests for `intercept check` (pure function).**
   - Synthesizes a fake `state.db` from in-memory sessions
   - Uses a temp `intercept.toml` with various rules
   - Asserts the decision is `allow` / `throttle` / `prompt`
   - 64 unit + integration tests ship in v0.4.0-beta (10/10
     runs green); coverage grows with each new rule variant

2. **Unit tests for state.db failure modes** (new for v0.4.0 final).
   - **state.db missing:** run `intercept check` when the
     file path is `None` (no home dir) or doesn't exist. Must
     return `allow` with exit 0, log a stderr message, **not
     panic**.
   - **state.db locked:** spawn two processes — one holds an
     exclusive lock on a temp `state.db` (simulating Hermes
     actively writing), the other runs `intercept check`.
     Must return `allow` with exit 0, log a stderr message.
   - **state.db corrupt:** write garbage to a temp `state.db`.
     Must return `allow` with exit 0, log a stderr message.
   - All three tests are deterministic (no race) because we
     use temp files with explicit file locking.

3. **Integration tests for the shim.**
   - Spawns the shim with a fake `agent0waste` on PATH
   - The fake `agent0waste intercept check` returns a
     pre-canned decision (allow / throttle / prompt)
   - Asserts: the wrapped command runs, the throttle sleeps
     the cooldown, the prompt reads from stdin, the timeout
     triggers a fail-open with stderr log
   - **Timeout test:** fake `agent0waste` sleeps 10s; shim
     must kill at 5s and run the real command within 5.5s
   - **No-PATH test:** empty `PATH`; shim must log
     `agent0waste: not on PATH; running unwrapped.` and run
   - ~8 tests

4. **End-to-end test against real data.**
   - Uses the real `~/.hermes/state.db`
   - Runs `intercept check` with various model/tokens flags
   - Asserts the decision matches the v0.3.0 heuristic output
     for the same period
   - This is the test that proves "Layer 4 is consistent with
     Layer 3"

## Migration from v0.3.1 to v0.4.0

## What v0.4.0 is *not*

- Not a Hermes replacement. Hermes still runs. Agent0Waste
  just wraps it.
- Not a daemon. No background process. The wrapper is per-call.
- Not a network service. The wrapper talks to local files only.
- Not a config editor. We never touch `~/.hermes/config.yaml`.
- Not a model router. We don't pick models; we observe calls.
- Not a cost forecaster. We don't predict next month's spend.
  We act on the recent past.

The v0.4.0 design preserves every non-goal from v0.1 through
v0.3.1. The user can disable Layer 4 at any time with
`agent0waste intercept disable` and the wrapper is gone.
