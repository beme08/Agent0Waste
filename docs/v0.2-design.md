# Agent0Waste v0.2 — Accounting Layer

**Goal:** Measure actual token consumption of AI tools you run, estimate cost,
surface waste you can't see from a static config scan.

## Confirmed decisions

| Question | Decision |
|---|---|
| Scope (frameworks) | **Hermes only** (Claude Code, Goose, etc. deferred to v0.3+) |
| Platform | **macOS first**, then Linux/Windows |
| Pricing strategy | **Built-in average pricing + optional `~/.config/agent0waste/pricing.toml` override** |
| Tracking mechanism | **`run -- <cmd>` wrapper** (not a daemon) |
| Export format | **JSON only** (CSV only if you ask for it later) |
| Trend window | **7-day rolling** (configurable via `--since Nd`) |

## Tracking mechanism: `run -- <cmd>` wrapper

```bash
agent0waste run -- hermes            # wrap hermes, record session
agent0waste run -- claude            # works for any command
```

**How it works:**
- Forks the wrapped command as a child process
- Passthrough stdin/stdout/stderr (you interact normally)
- Records wall-clock time, command, exit code
- Parses output for token counts (most agent CLIs log `input: X / output: Y`)
- Writes a session JSON record on exit

**Why not a daemon:**
- Daemon needs lifecycle management (start/stop, what to track)
- Daemon can't easily attribute tokens to specific commands
- Daemon requires running 24/7 — wastes resources when not using AI
- Wrapper is single-shot, matches the existing CLI usage pattern

**Trade-off:** tokens are estimates unless the tool logs them explicitly. This is
fine for the goal ("how much did I spend today?") — exact billing is not the
point.

## Session schema

One JSON file per session at `~/.local/share/agent0waste/sessions/<session_id>.json`:

```json
{
  "session_id": "sess_2026-06-02T15-30-15_a1b2c3",
  "started_at": "2026-06-02T15:30:15Z",
  "ended_at": "2026-06-02T15:42:08Z",
  "duration_s": 713,
  "exit_code": 0,
  "command": "hermes",
  "command_args": ["-p", "fix the bug"],
  "agent_profile": "hermes-core",
  "model": "grok-4.3",
  "provider": "xai-oauth",
  "is_local": false,
  "tokens": {
    "input": 4521,
    "output": 12803,
    "total": 17324
  },
  "cost_usd": {
    "input": 0.0226,
    "output": 0.1920,
    "total": 0.2146
  },
  "tools_used": ["web", "browser", "computer_use"],
  "notes": "Parsed 3 tool invocations from tool log lines"
}
```

**Storage:** 500-session FIFO cap (oldest dropped when full). JSON-per-file
keeps the format inspectable; no SQLite needed at this scale.

## Commands

```bash
agent0waste run -- <cmd>            # wrap a tool, record session
agent0waste sessions                # list recent sessions (table)
agent0waste sessions --json         # same, JSON output
agent0waste cost                    # total cost, all time
agent0waste cost --since 7d         # last 7 days (default)
agent0waste cost --since 30d        # last 30 days
agent0waste cost --by model         # breakdown by model
agent0waste cost --by tool          # breakdown by tool name
agent0waste cost --export json      # machine-readable export
```

Unknown models → `"$?.??"` placeholders + a warning line in `cost` output.

**Override file:** `~/.config/agent0waste/pricing.toml`

```toml
[grok-4.3]
input = 5.00
output = 15.00

[claude-sonnet-4.6]
input = 3.00
output = 15.00
```

Override takes precedence over defaults. Schema is `[model-name]` → `input` /
`output` in $/1M tokens.

## Token estimation strategy

Three-tier fallback (in order of accuracy):

1. **Parse tool output** for log lines like `input tokens: 4521` / `output: 12803`
   — most agent CLIs already log this; we just grep for it
2. **Heuristic from output length**: `tokens ≈ chars / 4` for stdout text
3. **Skip with warning** if neither produces a number; cost shown as `?`

Tiers 1+2 give approximate numbers. For your own daily use, "I spent about $0.20
in that session" is plenty useful; exact billing is not the goal.

## Trends

- Default window: **7 days** (matching common weekly review cycles)
- Configurable via `--since Nd` (e.g., `--since 30d`, `--since 1d`)
- Bucketed by day, shown as table:

```
Date         Sessions   Tokens     Cost
2026-05-27   3          48.2k      $0.31
2026-05-28   5          81.7k      $0.55
...
2026-06-02   4          62.1k      $0.42
─────────   ────       ────────    ─────
TOTAL        28         412.3k     $2.74
```

No charts. We're a CLI, not a dashboard.

## Not in v0.2 (deferred)

- Real-time proxy / interception (Layer 4)
- Cross-session context compression savings
- Per-prompt token breakdown (per session only)
- Charts / dashboards / TUI
- SQLite backend (JSON files fine at this scale)
- Claude Code / Goose / aider support (v0.3+)

## Implementation order

1. `pricing.rs` — defaults + override loader, no deps
2. `sessions.rs` — JSON record read/write, no deps
3. `run.rs` — child process wrapper, depends on sessions
4. `cost.rs` refactor — uses sessions + pricing
5. `main.rs` — wire up `run`, `sessions`, `cost` subcommands
6. README + demo updates
7. Tag `v0.2.0-beta` after green-light test
